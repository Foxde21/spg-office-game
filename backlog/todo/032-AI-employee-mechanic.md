# AI-Сотрудник: Механика автономного героя на базе LLM

## Описание

Добавить второй игровой режим, в котором героем управляет не игрок вручную, а LLM-модель. Игрок задаёт профиль персонажа (роль, навыки, уровень знаний, характер), подключает свой LLM API-ключ — и наблюдает, как AI-сотрудник самостоятельно проходит карьерный путь от Junior до Team Lead. Текущий ручной режим остаётся без изменений.

---

## Два игровых режима

### Режим 1: Ручной (текущий)

Уже реализован. Игрок управляет героем стрелками, взаимодействует с NPC клавишей E, сам принимает решения в диалогах и квестах.

### Режим 2: AI-Сотрудник (новый)

Игрок выступает в роли **наблюдателя/менеджера**. LLM-модель получает полный контекст игрового мира и самостоятельно принимает решения: куда идти, с кем говорить, какие квесты брать, какие ответы выбирать в диалогах.

## Системный промпт AI-сотрудника

LLM получает структурированный промпт, формируемый из профиля персонажа и текущего состояния игры.

### Структура промпта

```
Ты — {имя}, {роль} в IT-компании. Ты ведёшь себя как реальный сотрудник.

## Твой профиль
- Роль: {роль}
- Уровень знаний: {уровень}/10
- Характер: {список черт}
- Специализация: {список}
- Мотивация: {мотивация}
- Слабости: {список}
- Стиль общения: {стиль}
- Биография: {био}

## Текущее состояние
- Карьерный уровень: {junior/middle/senior/lead}
- Стресс: {0-100}
- Уважение: {0-100}
- Текущая локация: {локация}
- Активные квесты: {список}
- Инвентарь: {список предметов}
- Отношения с NPC: {список}

## Доступные действия
1. MOVE_TO:{локация} — перейти в другую локацию
2. TALK_TO:{npc_id} — начать диалог с NPC
3. PICK_UP:{item_id} — подобрать предмет
4. USE_ITEM:{item_id} — использовать предмет
5. CHOOSE:{choice_index} — выбрать вариант ответа в диалоге
6. WAIT — подождать / отдохнуть
7. CHECK_QUESTS — посмотреть квесты

## Правила
- Отвечай ОДНИМ действием в формате JSON
- Обоснуй решение в поле "reasoning"
- Учитывай свой характер, слабости и мотивацию
- Если стресс высокий — склоняйся к отдыху (но характер может мешать)
- Если уважение низкое — старайся заработать его (по-своему)
```

### Формат ответа AI

```json
{
  "action": "TALK_TO",
  "target": "tim-lead",
  "reasoning": "Хочу узнать про новые задачи, моя мотивация — карьерный рост",
  "emotion": "уверенность",
  "innerThought": "Нужно показать себя перед лидом, возьму сложную задачу"
}
```

## Цикл принятия решений (AI Game Loop)

```
┌─────────────────────────────────────────────┐
│  1. Собрать текущее состояние игры           │
│  2. Сформировать промпт с контекстом         │
│  3. Отправить запрос к LLM                   │
│  4. Распарсить ответ (action + reasoning)    │
│  5. Валидация действия (доступно ли оно?)    │
│  6. Выполнить действие в игровом мире        │
│  7. Показать мысли AI в UI                   │
│  8. Подождать (настраиваемая задержка)       │
│  9. Повторить                                │
└─────────────────────────────────────────────┘
```

### Обработка ошибок LLM

| Ситуация | Поведение |
|----------|-----------|
| LLM вернул невалидный JSON | Повторный запрос (до 3 раз), затем WAIT |
| LLM выбрал недоступное действие | Отфильтровать, запросить снова с уточнением |
| Таймаут запроса | Действие WAIT, уведомление в UI |
| Исчерпан API-лимит | Пауза игры, уведомление игроку |
| Зацикливание (>5 одинаковых действий) | Принудительная смена контекста, подсказка в промпте |

## Механика «Вмешательство»

Игрок может нажать «Вмешаться» в любой момент и:

1. **Подсказать** — добавить текст в контекст следующего запроса LLM:
   - «Поговори с Анной HR про отпуск»
   - «Сейчас лучше отдохнуть»
   - «Возьми квест у Тим Лида»

2. **Выполнить действие вручную** — перехватить управление на 1 действие

3. **Изменить приоритеты** — временно добавить в промпт:
   - «Сейчас сфокусируйся на снижении стресса»
   - «Приоритет — повышение уважения»
   - «Выполни квест X»

Вмешательство работает как «внутренний голос» персонажа и вписывается в промпт как:
```
## Подсказка от наблюдателя
{текст игрока}
Учти эту подсказку при следующем решении, но фильтруй через свой характер.
```

## Система памяти AI-сотрудника

### Краткосрочная память (контекст LLM)

- Последние 10-15 действий и их результаты
- Текущий разговор (до 6 сообщений)
- Активные квесты и прогресс

### Долгосрочная память (хранение на клиенте)

Структура в `localStorage` / `GameState`:

```typescript
interface AIMemory {
  importantEvents: Array<{
    event: string
    emotion: string
    timestamp: number
  }>
  npcImpressions: Record<string, string>
  lessonsLearned: string[]
  failedStrategies: string[]
  currentGoal: string
}
```

Долгосрочная память передаётся в промпт как сжатая сводка:

```
## Твои воспоминания
- Тим Лид: "Отличный наставник, помог с первым код-ревью"
- Петя Сеньор: "Жёсткий, но справедливый"
- Урок: "Не стоит брать 3 квеста одновременно — стресс резко растёт"
- Неудачная стратегия: "Игнорирование побочных квестов ведёт к потере уважения"
- Текущая цель: "Получить повышение до Middle"
```

## Влияние профиля на поведение

### Примеры зависимости от характера

| Черта | Поведение AI |
|-------|-------------|
| Интроверт | Избегает разговоров, предпочитает квесты с предметами |
| Экстраверт | Постоянно общается с NPC, берёт социальные квесты |
| Амбициозный | Берёт сложные квесты, рискует стрессом ради уважения |
| Расслабленный | Часто отдыхает, медленный карьерный рост |
| Перфекционист | Долго на каждом квесте, но получает бонус уважения |
| Прокрастинатор | Иногда пропускает ходы (WAIT), откладывает сложное |
| Конфликтный | Может выбирать агрессивные варианты в диалогах |
| Импостер-синдром | Избегает сложных квестов, больше стресса от ревью |

### Влияние уровня знаний

| Уровень | Эффект |
|---------|--------|
| 1-3 | LLM чаще ошибается в выборах, стресс от ревью выше |
| 4-6 | Сбалансированное поведение |
| 7-9 | Уверенные решения, быстрый рост уважения |
| 10 | «Гений» — иногда overconfident, конфликты с коллегами |

## Дополнительные механики

### 1. Мульти-AI-симуляция

Запуск нескольких AI-сотрудников одновременно с разными профилями. Наблюдение, какой характер/стратегия лучше работает. Таблица лидеров между AI-сотрудниками.

```
┌──────────────────────────────────────────────┐
│  AI-Турнир: Кто быстрее станет Lead?          │
├──────────────────────────────────────────────┤
│  1. 🏆 Алексей (Амбициозный) — Senior, день 45│
│  2. 🥈 Мария (Сбалансированная) — Middle, д. 45│
│  3. 🥉 Игорь (Расслабленный) — Junior+, д. 45 │
│  4. ❌ Дима (Конфликтный) — Уволен, день 32    │
└──────────────────────────────────────────────┘
```

### 2. Режим «AI vs Игрок»

Параллельное прохождение: игрок проходит вручную, AI-сотрудник — автоматически. В конце сравнение результатов: кто быстрее, у кого стресс ниже, кто больше квестов выполнил.

### 3. Режим «AI-Менеджер»

Инверсия ролей: игрок — директор, который управляет командой AI-сотрудников. Можно:
- Назначать задачи конкретным AI
- Перераспределять нагрузку
- Отправлять на обучение/отдых
- Нанимать/увольнять

### 4. Повторяемость и анализ (Replay + Analytics)

- Запись всех действий AI в воспроизводимый лог
- Графики: стресс, уважение, карьерный рост по времени
- Тепловая карта: какие локации AI посещает чаще
- Аналитика решений: % агрессивных/осторожных/социальных действий
- Экспорт истории в JSON для анализа

### 5. «Генетический алгоритм» профилей

- Запуск серии AI-сотрудников с разными параметрами
- Автоматический отбор лучших профилей
- Мутация параметров для следующего поколения
- Нахождение «оптимального сотрудника»

### 6. Стриминг мыслей

Показ потока сознания AI в реальном времени. Текст появляется постепенно (streaming response). Создаёт эффект «подглядывания за мыслями» живого человека.

### 7. Дневник AI-сотрудника

В конце каждого «рабочего дня» LLM генерирует запись в дневнике:

```
День 5. Сегодня был сложный день. Утром Петя раскритиковал мой код —
обидно, но он прав. Потом Анна HR позвала на тимбилдинг — стресс 
немного ушёл. Взял новый квест от Тим Лида. Чувствую, что расту.
Завтра постараюсь закрыть баг-репорт от Маши.
```

### 8. Настроение и эмоциональная модель

AI-сотрудник имеет эмоции, влияющие на решения:

```typescript
interface AIEmotionalState {
  mood: 'happy' | 'neutral' | 'stressed' | 'angry' | 'sad' | 'excited'
  energy: number       // 0-100
  motivation: number   // 0-100
  confidence: number   // 0-100
}
```

Эмоции меняются от событий и передаются в промпт. Визуализация: иконка настроения над персонажем.

### Хранение API-ключа

- Ключ хранится **только** в `localStorage` браузера
- Передаётся на сервер в каждом запросе через заголовок `Authorization`
- Сервер **не сохраняет** ключ — только проксирует
- При закрытии вкладки ключ остаётся в localStorage (по желанию пользователя)
- Кнопка «Удалить ключ» в настройках

### Эндпоинт для AI-сотрудника

```
POST /api/ai/employee
Headers:
  X-User-API-Key: <ключ пользователя>
Body:
{
  "messages": [...],
  "model": "meta-llama/llama-3.1-8b-instruct:free",
  "max_tokens": 300,
  "temperature": 0.7
}
```

Сервер использует переданный ключ вместо серверного `OPENROUTER_API_KEY`.

## Критерии приемки

1. В главном меню доступен выбор между «Ручной режим» и «AI-Сотрудник»
2. Экран создания профиля AI-сотрудника с валидацией полей
3. AI-ключ корректно хранится и передаётся через прокси-сервер
4. AI-цикл работает: герой автономно ходит, общается, выполняет квесты
5. UI наблюдателя показывает мысли, действия и статистику
6. Кнопки управления (пауза, ускорение, стоп, вмешательство) работают
7. Механика «Вмешательство» корректно модифицирует промпт
8. AI-память сохраняется между сессиями
9. Обработка ошибок LLM: таймауты, невалидные ответы, лимиты
10. Профиль персонажа влияет на поведение AI
