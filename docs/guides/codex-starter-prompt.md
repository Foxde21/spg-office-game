# Codex starter prompt

Готовый prompt для нового члена команды, использующего **Codex CLI** на проекте Office Quest. Юзер вставляет его как первое сообщение в свежей сессии Codex — агент сразу понимает контекст, флоу, и просит выбрать задачу.

> **Если ты пользуешься Claude Code** — этот файл тебе не нужен: Claude автоматически читает `CLAUDE.md` (который импортит `AGENTS.md`). Иди в [`docs/guides/onboarding.md`](onboarding.md).

## Как пользоваться

1. На свежем клоне репо один раз поставь slash-команды Codex:

   ```bash
   mkdir -p ~/.codex/prompts
   cp .codex/prompts/{new-story,start-story,finish-story,adr}.md ~/.codex/prompts/
   ```

   Если ставить лень — пропусти; ниже в промпте указано как обходиться без них.

2. В корне проекта запусти Codex CLI.
3. Скопируй блок ниже целиком и отправь как первое сообщение.

## Сам prompt (копировать целиком)

```text
Привет, Codex. Ты помогаешь команде на Office Quest — это обучающая платформа для джуниор AI-специалистов, оформленная как 2D point-and-click игра. Кодовая база сама по себе — учебное пособие, поэтому флоу разработки намеренно простой и чистый.

Перед любой работой прочитай в этом порядке:

1. `AGENTS.md` — ориентация: где что лежит, конвенции, какую роль играть.
2. `docs/guides/onboarding.md` — твои первые 30 минут на проекте (написано для junior, тебе тоже полезно).
3. `docs/requirements/00-index.md` — карта модулей и список открытых вопросов (Q1-Q14). Если стори, которую ты делаешь, упирается в открытый вопрос — стой и эскалируй человеку.

Slash-команды (если установлены в ~/.codex/prompts/):
- /new-story "<заголовок>" — скаффолдит новую стори в backlog/todo/.
- /start-story OQ-XXX — DOR-чек, ветка от dev, перенос в in-progress, атомарный коммит.
- /finish-story OQ-XXX — DOD-чек, перенос в done, атомарный коммит, PR в dev.
- /adr "<заголовок>" — скаффолдит новый ADR в docs/architecture/.

Если slash-команды НЕ установлены — следуй мануальному чеклисту в backlog/README.md "Manual checklists for Codex CLI / no-tool users". Каждая команда там расписана step-by-step.

Working principles для этого репо:
- Источник правды по поведению — docs/requirements/. Меняешь поведение → сначала обнови requirement-файл, потом код.
- Три роли в .claude/agents/: ba-analyst, game-dev, code-reviewer. Прочитай ту что подходит задаче и играй её. Не изобретай четвёртую.
- Бранчинг 3-уровневый строго: main ← dev ← feature/* (или bugfix/, refactor/, docs/). Никогда не коммитим напрямую в main или dev.
- Story IDs: новые — OQ-XXX, legacy 001-034 остаются как есть. Следующий новый id — посмотри backlog/{todo,in-progress,done} и +1.
- Атомарные коммиты в /start-story и /finish-story: file move + frontmatter status flip + AC ticks + changelog ВСЁ В ОДНОМ коммите. Перед git commit — проверь что staged-файл действительно содержит новый status и новый changelog (sanity-check обязателен).
- DOR / DOD — гейты. Не пропускай "just this once".
- Никаких console.log, any, magic-чисел в shipped-коде. ToastManager для нотификаций.

Что хочешь сегодня сделать?

Если берёшь стори из backlog/todo/ — прочитай её целиком прежде чем что-то менять. Замапь каждый AC на тест или на строку кода.
Если предлагаешь новую работу — запусти /new-story (или мануальный equivalent), сначала скаффолд, потом — содержание (BA-роль).
Если упираешься в открытый вопрос или дизайн-call — НЕ угадывай, эскалируй человеку или предложи открыть ADR через /adr.
```

## Когда обновлять этот промпт

Промпт не должен расти бесконтрольно — это первое сообщение, его читают каждый раз. Обновлять — когда:

- В репо появляется новая корневая директория, без которой junior'у не обойтись.
- Меняется список slash-команд (добавили / удалили / переименовали).
- Появляется/уходит роль в `.claude/agents/`.

Не добавлять сюда:

- Узкие правила стиля (живут в `docs/contributing.md` и `AGENTS.md`).
- Описание конкретных стори / эпиков / waves (агент сам прочитает `backlog/roadmap.md`).
- Длинные guidelines про TDD / архитектуру (агент прочитает `AGENTS.md` и `docs/requirements/`).
